# Inborn design review — 2026-09-06

Reviewer: product-designer stream. Scope: the app as built on branch `main` (`b7e6b24`) against the
binding spec in `docs/spec-src/` (FARADAY §9, screens §8, brand §3.4, vision §2.3).

## How this was verified

- **Web export** (`pnpm web:build` + `web:serve`) rendered in headless Chromium (playwright-core) at
  phone 390x844 and desktop 1180x800, in dark and light, for onboarding S01-S05, chat empty S10,
  chats drawer S20, proof S50, settings S52 and its sub-pages, and the paywall S60. Screenshots are
  under `…/scratchpad/shots/` (paths listed per finding).
- **Source audit** of every component named below, checked line by line against the spec tokens and
  motif definitions.
- **Not run: iOS simulator and Android emulator.** Two devices (the OnePlus and `emulator-5556`) are
  already held by other streams, and the standing operations rule forbids booting a third heavy AVD
  after a prior out-of-memory incident. The consequence for these findings is stated where it matters:
  the font fallback and the platform-native chrome are the two areas that can only be fully confirmed
  on device. Everything else is component code shared across web and native, so the web render is
  faithful to what ships.
- **The Vault (S30) could not be rendered** in the headless web harness: it throws
  `Cannot read properties of undefined (reading 'get')` when the on-device engine/OPFS is absent,
  which is always the case in headless Chromium. It is reviewed at code level only. Confirm it on a
  device or a real browser with a loaded model.

## What is right — keep it

- **Palette matches §9.2 exactly**, both themes (`packages/ui/src/tokens.ts`): every bg/surface/well/
  border/text/accent/sealed/danger/cta value is the spec value, including the light-mode accent-as-text
  darkening and the glow/bloom staying amber in both schemes.
- **The seal (§9.5.1) is excellent** (`components/Seal.tsx`): all five states plus `open` and `lan`,
  the 1.6s breathing while generating, the 420ms spring close with one rigid haptic and a 600ms green
  bloom, and a correct reduced-motion path (static ring, no bloom).
- **All five motifs are present**: chip glyph (§9.5.2), zero-egress readout (§9.5.3), the collapsed
  Ledger receipt (§9.5.4), and the model cartridges with state dot, battery tag, speed range and
  filament load bar (§9.5.5).
- **Chat anatomy (§9.6) is faithful**: flat full-width answers with a mono label, the quiet user
  bubble (surface-1, radius 14 with a 4px bottom corner, 85% max), the pulsing-dot waiting window, the
  streaming caret, stopped/loop/error states with the right recovery actions, per-message bidi
  direction, the 2px context hairline, and the composer well with an amber-60% focus border and 44px
  targets.
- **Markdown (§7.1/§7.8) is strong** (`components/chat/Markdown.tsx`): tables and code stay LTR inside
  RTL, a streaming code block stays plain text until its closing fence then snaps to code, the code
  header has a copy action, wide content scrolls inside its own container (never the page), and links
  are text-only so nothing can start a request.
- **Onboarding S01-S05, Proof S50, Settings S52** render faithfully in both themes; light-theme
  contrast is healthy (secondary text, mono captions and green labels all legible on the light
  surfaces).
- **Radii, spacing and motion tokens match §9.4**, and reduced-motion + haptics are wired through the
  seal and the peak moments.

## Deliberately not done

- iOS simulator and Android emulator runs (device contention + the standing no-third-emulator rule).
  Findings #1 and #3 are the only ones whose on-device behaviour differs from the web render, and both
  are called out as needing device confirmation.
- Vault S30, Model details S31, Voice S44, Documents library S40, and the desktop/Tauri doors were not
  rendered (harness limits / out of web scope); S30/S31/S40 are reviewed at code level.

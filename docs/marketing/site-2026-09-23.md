# The Inborn website, round 41 — 23.9.2026

`apps/site` stops being a document set and becomes a landing page: a hero the reader can type into, seven numbered
sections, ten FAQ answers written for answer engines, a three-post blog, and the structured data and crawler files that
let an answer engine quote us. Still plain HTML and CSS, still zero JavaScript in the output, still zero third-party
requests. Build `pnpm --filter @inborn/site build`, gate `pnpm --filter @inborn/site check`. **Nothing is deployed.**

## The hero composer

A reader types a first message on the site and lands in the web app with it ready. Zero JavaScript, so it is a plain
`GET` form:

```
<form class="composer" action="https://app.inbornapp.com/" method="get"> … <input name="q"> … </form>
```

- `APP_ORIGIN` (default `https://app.inbornapp.com`) sets both the form action and the CSP `form-action`. The web app
  is not deployed anywhere yet; `app.inbornapp.com` is the subdomain on our own zone reserved for it. **Open ask:** the
  lead sets the DNS record and deploys `apps/web/dist` there, or overrides `APP_ORIGIN` at build time.
- `public/_headers` carries `{{APP_ORIGIN}}`, filled at build. The CSP was `form-action 'none'`, which would have
  blocked the form; it now names exactly one origin and nothing else. `script-src 'none'` is now explicit, so the gate's
  assertion is no longer vacuous.
- The app side reuses the share-target seed that already exists (`openShared` → `active.seed` → `Chat`), so the message
  survives the download door and onboarding and appears in the composer of the first chat. Only the web stub changed:
  `apps/mobile/src/share/useShareTarget.ts` reads `?q=` once per load, clears it from the address bar with
  `history.replaceState`, and hands it over as a `text` payload.
- **Honesty, on the page:** a `GET` form puts the typed line in the URL, so it reaches the app origin's access log. The
  note under the composer says so in plain words. On a page whose whole claim is "nothing leaves", shipping that
  silently was not an option.

## The GitHub link, which is not there

Moshe asked for a link to GitHub and for "source-available". `github.com/moshecohen90/inborn` is **private**: verified
anonymously this round, `https://github.com/moshecohen90/inborn` returns **404** and the unauthenticated API returns
`Not Found`. `docs/legal/verification.md` forbids publishing "open source", "published core", "reproducible build" or
"a source link the reader cannot open" while the repository is private, and F99 is the round where exactly those claims
had to be stripped out of eight store listings.

So the site says what is true instead: "Inborn's source code is not public, so none of the checks above asks you to read
it, and there is no public issue tracker." That line is in the Get section, the footer and the FAQ. The FAQ answer to
"Is Inborn open source?" is a plain no. **Decision for Moshe:** the day the repository goes public, the source-available
answer and the link go in together. One line in `build.mjs` and one FAQ entry; it is not a rebuild.

## Store links

Both listings were verified this round and **neither is public**: the App Store version for app id `6809165161` is
`PREPARE_FOR_SUBMISSION` and `apps.apple.com/us/app/id6809165161` returns 404; the Play listing for
`com.inbornapp.mobile` returns 404 because vc19 went to the **internal** track, not production.

Per the brief the download row links the real product pages anyway and marks the state on screen ("Opens at launch").
`STORES_LIVE=1` flips the label to "Download Inborn" with no other change. Two consequences worth knowing:

- Apple's marketing guidelines require the badge artwork to link directly to a live product page, so the row uses
  **text tiles, not the official badges**. That is compliant today and it keeps the zero-third-party-request rule. When
  both listings are live, self-host Apple's SVG from `toolbox.marketingtools.apple.com` and the Play badge from the
  Partner Marketing Hub, inline them, and keep the Apple trademark line that is now in the footer.
- `<meta name="apple-itunes-app" content="app-id=6809165161">` is worth adding on launch day and does nothing before
  then (Safari hides the banner for an app that is not available). Not added yet.

Campaign links for launch day, from Apple's and Google's documentation:

```
https://apps.apple.com/app/apple-store/id6809165161?pt=<PROVIDER_TOKEN>&ct=site-home&mt=8
https://play.google.com/store/apps/details?id=com.inbornapp.mobile&referrer=utm_source%3Dinbornapp.com%26utm_medium%3Dweb%26utm_campaign%3Dsite-home
```

Do not pin `hl=` / `gl=` or a country path segment: both stores geo-route, and pinning hurts the seven non-English
launch locales.

## SEO, AEO and structured data

- **JSON-LD ships, and the gate still blocks real scripts.** `<script type="application/ld+json">` is a *data block*:
  WHATWG's "prepare the script element" returns before the Content Security Policy step, so it never executes and never
  trips `script-src 'none'`. `check.mjs` now allows exactly that one element shape, parses the JSON, requires
  `@context` to be schema.org, rejects a raw angle bracket inside it, and fails any page that has no JSON-LD at all.
  Everything else matching `<script` is still fatal.
- Graph per page: `WebSite`, `Organization`, `Brand` everywhere; `SoftwareApplication` with three `Offer` nodes and
  `FAQPage` on the landing page; `Blog` on the index; `BlogPosting` and `BreadcrumbList` on each post. **No
  `aggregateRating`** until real store ratings exist. Google's `FAQPage` rich result was removed in May 2026, so the
  markup is there for other engines and for extraction, not for a Google SERP feature.
- The ten FAQ answers live in `FAQ` in `build.mjs` and render **both** the visible `<h3>` list and the `FAQPage` graph,
  so a quoted answer can never differ from the answer a reader sees.
- Each answer states the whole thing in its first sentence, 40 to 75 words, and names Inborn in the first clause, so a
  chunk lifted out of the page still stands alone. The comparative material (models, tiers, speeds) is in real tables.
- `robots.txt` allows every engine that can cite us, including `GPTBot`, `ClaudeBot`, `Google-Extended`,
  `Applebot-Extended` and `CCBot`, and blocks the data resellers (`Bytespider`, `omgili`, `Diffbot` and friends).
  `facebookexternalhit` is deliberately allowed: blocking it would kill link previews. A `Content-Signal` line states
  `ai-train=yes` explicitly, because Cloudflare's managed default is `no` and would otherwise contradict us silently.
- `sitemap.xml` drops `priority` and `changefreq` (Google ignores both) and takes `lastmod` from **git**, not from build
  time. A build-time stamp claims every page changed on every deploy, Google checks, and then distrusts the field for
  the whole site.
- `llms.txt` follows the llmstxt.org shape and is generated from the same page list, so it cannot drift.
  `llms-full.txt` is the whole site as text in one fetch. Neither is a ranking channel; they cost nothing and they are
  the file a person hands to a model.
- Open Graph: `1200x630` PNG cards in `public/og/`, rendered from the site's own tokens and fonts by the script in the
  session scratchpad. `og:image` cannot be an SVG: LinkedIn, X, WhatsApp, Slack and Discord all fail silently on one.
  The previous `icon-512.png` was square and rendered as a thumbnail rather than a card.
- Not done: a "best offline AI apps for iPhone and Android" comparison post, which the ASO read named as the single
  highest-value missing page for web organic. Out of scope for this round.

## Design

An identity derived from the app rather than a template, using only the FARADAY tokens already in
`packages/ui/src/tokens.ts`. No new colours, no images, no icon set.

- **The Faraday screen.** A fine CSS mesh behind the hero, masked with a radial fade. It is the only ornament on the
  site and it is drawn in two `repeating-linear-gradient`s, so the page still fetches nothing.
- **The seal in a port.** At 1024 and up the product's mark sits in a bordered circular well on the right of the hero,
  which reads as an instrument panel rather than a logo dropped onto a page.
- **A numbered rail.** Every section carries a monospace number and label in a sticky left rail at 1024 and up, and a
  hairline rule across the full column. Below 1024 the rail folds to a single line above the heading. This is what keeps
  the wide layout from being a phone screen stretched sideways.
- **Monospace readouts** as the recurring device: the hero readout, section numbers, sizes, speeds and the footer line.
- Fluid type with `clamp()`, body copy capped at 68 to 74 characters, tables scrolling inside `.table-wrap` so the page
  itself never scrolls sideways, and every control at least 44px tall. At 640 and below the header folds to two rows so
  the brand, three links and the button each keep their target size.

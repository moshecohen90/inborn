05ארכיטקטורה טכנית

שלושה עקרונות מכתיבים את הארכיטקטורה: אין שרת בלולאה של השימוש, כל נתון של המשתמש מוצפן במנוחה, וכל רכיב שנוגע ברשת מבודד לנתיב אחד ויחיד שאפשר לבקר.

5.1 נתיב הרשת: אפס באנדרואיד, אחד ומבוקר בשאר

העיקרון: האפליקציה עצמה לא פותחת socket בשום פלטפורמה שבה אפשר להימנע מזה. אין analytics, אין crash reporting מרחוק, אין remote config, אין push, אין SDK פרסום, אין בדיקת גרסה. כך מגיעים מודלים ורכישות בכל פלטפורמה:

  • ההורדה היא פעולה מפורשת עם מסך משלה, מונה בייטים וביטול. לעולם לא הורדה ברקע בלי לחיצה (חבילת ה‑fast‑follow באנדרואיד היא של Play, גלויה במסך ההורדות, ומוצגת למשתמש ב‑S02).
  • מד יציאה גלוי: מסך ההוכחה מציג OUT 0 B שנצבר מאז ההתקנה. הורדות נספרות ב‑IN בלבד. אם אי פעם יתווסף מסלול ענן אופציונלי, החותם נפתח (UNSEALED) והמשתמש רואה זאת.
  • שער CI: aapt2 dump permissions על כל APK/AAB לפני שחרור; כל SDK טרנזיטיבי (Firebase, RevenueCat, WebView SDKs) יכול להזריק INTERNET דרך מיזוג מניפסטים, ולכן אין אף SDK צד‑שלישי עם רשת. בניית CI שנכשלת אם ההרשאה מופיעה.
  • Sideload באנדרואיד (APK מחוץ ל‑Play) לא יכול להשתמש ב‑Asset Delivery: מקבל את Instant המובנה ואת נתיב הייבוא בלבד, ואומרים זאת.
  • מה מאבדים ומה מרוויחים: באנדרואיד אין חיפוש Hugging Face בתוך האפליקציה (המשתמש מוריד בדפדפן ופותח את הקובץ ב‑Inborn, שרשום כ‑handler ל‑.gguf), ומודל חדש בקטלוג מגיע עם עדכון אפליקציה. בתמורה: הטענה היחידה בקטגוריה שכל אחד יכול לאמת בדף החנות.

5.2 ממשק ההסקה LocalLM

ממשק אחד, בצורת ספק של Vercel AI SDK, כדי ששכבת הצ'אט לא תדע על איזו פלטפורמה היא רצה:

interface LocalLM {
  id: string;                       // "llama.rn" | "apple-fm" | "wllama" | "tauri" | "chrome-nano"
  capabilities(): { vision: boolean; tools: boolean; embeddings: boolean; maxContext: number };
  load(model: ModelRef, opts: { nCtx: number; gpuLayers?: number }): Promise<Session>;
  unload(): Promise<void>;
  generate(session, messages, opts: GenOpts, signal: AbortSignal): AsyncIterable<Delta>;
  embed(texts: string[]): Promise<Float32Array[]>;
  stats(): { tokPerSec: number; ttftMs: number; ctxUsed: number; memMB: number };
}
// Delta = { text?: string; reasoning?: string; toolCall?: ToolCall; done?: Usage }
  • Streaming תמיד עם AbortSignal; כפתור Stop הוא ביטול אמיתי, לא הסתרה.
  • בחירת מנוע אוטומטית: Apple FM אם זמין ומודל הפתיחה הוא הבחירה, אחרת GGUF. המשתמש רואה "מודל" אחד עם תיאור, לא רשימת מנועים.
  • תבניות צ'אט מגיעות מקובץ ה‑GGUF (Jinja) ומאומתות בקטלוג; המערכת לא מנחשת תבנית.
  • Tool calling מקומי בלבד: כלים כמו "חפש במסמכים שלי", "חשב", "תאריך היום" רצים במכשיר. אין כלי רשת.

5.4 קטלוג מודלים ומנהל הורדות

  • מניפסט חתום (Ed25519, המפתח הציבורי בתוך האפליקציה): לכל מודל שם, ספק, גודל, קוונטיזציה, sha256 לכל חלק, רישיון, RAM מינימלי, tier, יכולות (vision/tools), ותבנית צ'אט מאומתת. באנדרואיד המניפסט והחבילות מגיעים עם עדכון אפליקציה (אין נתיב רשת); ב‑iOS, בדסקטופ ובווב המניפסט מתרענן רק כשהמשתמש פותח את הכספת ומבקש לרענן.
  • מסירה: Android דרך Play Asset Delivery (fast‑follow ל‑Instant ול‑projector שלו, on‑demand לשאר; Play מטפל בהמשך, בסלולר ובאישור המשתמש); iOS, דסקטופ וווב מ‑Cloudflare R2 (אפס עלות egress; קטלוג של 60 GB עולה כדולר בחודש; 10,000 הורדות של 2.7 GB עולות 0 דולר לעומת אלפי דולרים ב‑CDN רגיל), Hugging Face כמראה גיבוי. אותו מניפסט חתום מתאר את כל הנתיבים. Apple‑hosted asset packs (Background Assets, iOS 26+) אינם בשימוש ב‑1.0 (תוקן 22.9.2026): אם יאומצו בעתיד, זו תהיה תוספת מתועדת, לא ברירת המחדל הנוכחית.
  • מה נשלח בתוך הבנייה עצמה (סבב 74, 24.9.2026): כל מודל שיש לו מסירת bundled בקטלוג יושב ב‑iOS בשורש ה‑.app בשם <id>.gguf (plugins/withBundledModel.js): היום Instant ו‑vision-qwen35. הכספת מסמנת אותם מוכנים כבר בסריקה הראשונה, llama.rn טוען אותם ישירות מה‑bundle (אפס בייטים מועתקים ל‑Documents), וה‑sha256 מחושב פעם אחת ברקע אחרי ההשקה הראשונה ונשמר. באנדרואיד, כל חבילת fast‑follow מתבקשת מ‑Play בסריקת האתחול. שער השחרור scripts/check-shipping-bundles.mjs פותח את ה‑archive ואת ה‑AAB ובודק שכל אחד מהקבצים האלה נמצא, בגודל וב‑sha256 של הקטלוג; בנייה בלי ה‑projector נכשלת. גודל ה‑IPA: 561 MB בבנייה 18, כ‑717 MB עם ה‑projector (הוא נדחס ל‑156 MB), הרבה מתחת לתקרת 4 GB של Apple; את סף ההורדה בסלולר Instant לבדו כבר עבר.
  • הורדה מה‑CDN (היכן שיש): חלקים (split GGUF) במקביל, המשך אחרי ניתוק, אימות hash לכל חלק ובסוף, בדיקת מקום פנוי לפני התחלה (גודל × 1.1), המשך ברקע מוגבל (iOS URLSession background) עם התראה מקומית בסיום.
  • ייבוא ידני: כל קובץ GGUF מהמכשיר (Files / SAF / drag‑and‑drop בדסקטופ; האפליקציה רשומה כ‑handler ל‑.gguf כך שהורדה בדפדפן נפתחת ישר בה). זו גם הדרך של משתמש פרנואיד להימנע לחלוטין מרשת, וב‑Android זו הדרך לכל מודל שאינו בקטלוג.
  • ניהול מקום: מסך הכספת מציג מה תופס מה, ומאפשר מחיקה. מודל שלא נטען 60 יום מוצע למחיקה (לא נמחק לבד).

5.5 מסמכים ו‑RAG על המכשיר

import → extract → (OCR if scanned) → chunk (fits the embedder: 212 tok, overlap 53 for e5) → embed → sqlite-vec → retrieve top‑k (k=6, MMR) → cite → generate extract: iOS PDFKit · Android PdfRenderer/pdfbox · Web/Desktop pdf.js · DOCX via mammoth · TXT/MD/CSV native OCR: iOS Vision · Android ML Kit Text Recognition (on‑device bundle) · Desktop Tesseract (Rust) · Web Tesseract.js embed: multilingual-e5-large-instruct Q6_K (468 MB, MIT, רב‑לשוני) — ה‑embedder היחיד שנשלח store: sqlite-vec (mobile/desktop) · in‑memory/IndexedDB (web)
  • כל תשובה שמבוססת על מסמך מציגה ציטוטים עם שם הקובץ ומספר עמוד; לחיצה פותחת את הקטע. בלי ציטוט, המודל אומר שלא מצא.
  • סף רלוונטיות בשני המצבים (cosine מעל 0.82 מספיק לבדו; מתחתיו נדרשת מילה משותפת אחת לפחות בין השאלה לקטע, ו‑cosine ≥ 0.5 יכול לחזק מילה משותפת אחת): רק קטעים מעליו נכנסים לפרומפט ורק הם הופכים לציטוטים. קודם הסף חל רק במצב "ענה רק מהמסמכים שלי", ולכן שאלה שאין עליה דבר במסמכים קיבלה תשובה מומצאת עם רשימת SOURCES מתחתיה (F161). כשאין קטע רלוונטי — או שהמסמך המצורף לא אונדקס בכלל — האפליקציה אומרת זאת בעצמה: "Nothing in your documents matched this question. Answered without them.", ולא סומכת על כך שמודל קטן יציית להוראה. ההודעה הזו נשארת על המסך לצד התשובה שהיא מסבירה ויורדת רק כששאלה חדשה מחליפה את שתיהן; קודם היא הייתה הבזק של 1,400 מילישניות שנורה לפני שהתשובה התחילה, ועל טלפון שבו התשובה הראשונה מגיעה אחרי כ‑10 שניות היא נעלמה הרבה לפני שהיה מה להסביר (F276).
  • מסמך גדול (200+ עמודים) מאונדקס בהדרגה עם מד התקדמות, ואפשר לשאול על מה שכבר אונדקס.
  • שפות RTL ורב‑לשוניות: חיתוך לפי משפטים עם Intl.Segmenter, לא לפי תווים.
  • ה‑embedding רב‑לשוני ונשלח: מודל האינדקס של המסמכים הוא embed-e5, כלומר multilingual-e5-large-instruct בכימות Q6_K (468 MB, רישיון MIT, 512 טוקנים לטקסט). הוא החליף את nomic-embed-text-v1.5, שהוא מודל אנגלי. מדדנו 13 embedders ש‑llama.rn מריץ על אותן שאלות (docs/qa/embed-multilingual/measure.md, F333): במסמך בן שישה קטעים e5 מדרג את הקטע שעונה על השאלה במקום הראשון ב‑20 מתוך 21 שאלות, מול 3 מתוך 21 של nomic. בגרמנית, בעברית, ביפנית ובקוריאנית 3 מתוך 3. הקטע מחולק לפי חלון ה‑embedder: 212 טוקנים משוערים, כי המשערך מעריך קוד וטעמי המקרא בחסר עד פי 1.84 מול ה‑tokenizer של e5, ומה שעובר את 512 הטוקנים נקטע בטלפון וקורס בדסקטופ. שאלה ארוכה נחתכת לאותו תקציב לפני ה‑embedding (F335).
  • סינית ויפנית: בשפות שנכתבות בלי רווחים ההתאמה הלקסיקלית נעשית על צמדי תווים (bigrams), אחרת משפט שלם הוא אסימון אחד, שום קטע לא עובר את סף הרלוונטיות, והמשתמש מקבל "לא נמצא במסמכים" על שאלה שהמסמך שלו כן עונה עליה (F195).
  • מתי ה‑cosine מספיק לבדו: עם nomic הוא לא הספיק אף פעם. כששואלים מסמך בשפתו, שאלה שאינה על הנושא קיבלה 0.527–0.764 ביפנית, בסינית, בקוריאנית ובעברית, כלומר המספר מדד את השפה ולא את הנושא (F282/F327). עם e5 השאלה הגבוהה ביותר שאינה על הנושא, מתוך 144 שנמדדו בתשע שפות, מקבלת 0.8176. לכן הסף 0.82 פותח מחדש את הדלת של ה‑cosine לבדו, ולצידה נשאר הכלל הלקסיקלי של סבב 70. התוצאה במסמכים בני קטע אחד: 51 מתוך 57 שאלות על הנושא מקבלות ציטוט, ו‑0 מתוך 102 שאינן על הנושא. במסמכים בני שישה קטעים: 18 מתוך 21 מצטטות את הקטע הנכון, ואף אחת לא מצטטת רק קטע שגוי (F334). המרווח מעל השאלה הגבוהה ביותר שאינה על הנושא הוא 0.0024 בלבד, והסף קשור ל‑embedder הזה: החלפת embedder מחייבת מדידה חוזרת. החולשה שנשארה היא צרפתית: 1 מתוך 3. שלוש מתוך 42 שאלות שאינן על הנושא במסמכים בני שישה קטעים עדיין מקבלות ציטוט, וכולן דרך הכלל הלקסיקלי (שתי מילים משותפות עם קטע מאותו דוח), לא דרך ה‑cosine.
  • החלפת embedder בונה את האינדקס מחדש: לכל מסמך נשמר שם ה‑embedder שבנה אותו. מסמך שנבנה ב‑embedder אחר (כל מסמך שנבנה ב‑nomic) נבנה מחדש מהעמוד הראשון בפתיחה הראשונה אחרי העדכון, והשורות הישנות נמחקות. אם e5 עדיין לא הותקן, המסמך ממתין במצב "no-embedder" והצ'אט מבקש להתקין את אינדקס המסמכים, במקום לחפש וקטורים ממרחב אחר (F336).
  • מילות פונקציה בכל שפות ההשקה: רשימת ה‑stop words כללה אנגלית ועברית בלבד, ולכן שאלות בספרדית, פורטוגזית, צרפתית וגרמנית "התאימו" למסמך על el, de, la, le, von, sich — אותו כשל שתוקן לדבק הדקדוקי בסינית וביפנית (F278), בארבע מתוך שמונה שפות ההשקה. לכל שפת השקה יש כעת רשימה משלה (F327).

5.6 קול

  • תמלול (STT): iOS 26 SpeechAnalyzer (על המכשיר, מהיר), אחרת whisper.rn (whisper.cpp + Parakeet, Core ML). Android: whisper.rn או SpeechRecognizer אופליין. ווב: Transformers.js Whisper על WebGPU. הרשאת מיקרופון מתבקשת רק בלחיצה על המיקרופון.
  • הקראה (TTS): קולות מערכת (AVSpeechSynthesizer, Android TextToSpeech, Web Speech) בחינם ואופליין. קול נוירוני (Kokoro‑82M דרך ONNX) כשדרוג Pro בדסקטופ, לא בטלפון (כבד על CPU).
  • שיחת קול רציפה (hands‑free, VAD של Silero) היא פיצ'ר Pro שמובחן בשוק: Enclave היא היחידה שמציעה זאת מקומית.

סטטוס קוד, 22.9.2026 (ביקורת התאמה למפרט, פער 25). תשעה מרכיבים בתרשים §5.5 ובסעיף זה נקראים בשם ואינם בקוד היום ואינם ברשימת ה‑cut: mammoth (חילוץ DOCX), ML Kit Text Recognition (OCR אנדרואיד), Tesseract בדסקטופ (OCR), Qwen3‑Embedding‑0.6B ו‑all‑MiniLM (embedders), sqlite‑vec (גם ב‑§4.5), Apple SpeechAnalyzer, Core ML (Parakeet), Kokoro‑82M ו‑VAD של Silero. סטטוס: 1.0.1 — התרשים הוא התכנון שאליו בונים, לא הוכחה שהמימוש קיים; לפני שחרור 1.0 יש לאמת כל אחד מהם בקוד (ולסמן PROVEN/PARTIAL/MISSING כמו §10) או להסיר את השם ולתאר יכולת גנרית עד שהוא ייבנה. נוסף לרשימת ה‑"Intentionally not built for 1.0" ב‑README אם ייבדק כחסר.

5.8 ניהול זיכרון, חום וסוללה

  • לפני טעינה: קוראים זיכרון זמין (os_proc_available_memory ב‑iOS, ActivityManager.MemoryInfo ב‑Android) ומציגים רק מודלים שנכנסים (גודל × 1.4 + KV cache).
  • Entitlement increased-memory-limit ב‑iOS, mmap של ה‑GGUF, KV cache מוגבל ל‑2–4K טוקנים בטלפון (הגדלה ב‑Pro על מכשירי 8 GB+).
  • מצב חום .serious (iOS) או getThermalHeadroom (Android): מורידים GPU layers, מאטים, ומראים למשתמש "המכשיר חם, מאט כדי להגן עליו". במצב .critical עוצרים יצירה עם הודעה.
  • סוללה מתחת ל‑10% או Low Power Mode: בטלפון עוברים ל‑Instant מההודעה הבאה (עם "Switch back"), בנייד על סוללה רמה אחת למטה, בשולחני מחובר כלום; לעולם לא מריצים הסקה ברקע. הטבלה המלאה לפי סוג מכשיר וטריגר, כולל הקופי: §6.5.
  • אפליקציה שנכנסת לרקע באמצע יצירה: משלימה עד 15 שניות (background task) ושומרת חלקית; בחזרה מציעה "המשך".

5.10 ריבוי שפות מהיום הראשון

הוחלט (D13, משה 3.9.2026): משיקים ב‑6 שפות (§7.8), ובכל מקרה הקוד נבנה כך שהוספת שפה היא קובץ אחד ובלי שינוי קוד: כל מחרוזת בממשק חיה בקובץ locale אחד לכל שפה (JSON בפורמט ICU MessageFormat, עם ריבוי וסדר מילים לפי שפה), נטענת דרך i18next + react-i18next, ואותם קבצים משרתים את הטלפון, את הווב ואת הדסקטופ (Tauri מציג את הממשק מאותה בניית ווב). expo-localization קורא את שפת המכשיר; Intl מעצב תאריכים, מספרים ויחידות. RTL מהיום הראשון במבנה: מאפייני CSS לוגיים (start/end) ו‑I18nManager בכל מסך. מה נבדק בפועל בכל PR (מתוקן 22.9.2026): אף locale של עברית או ערבית לא נשלח ב‑1.0 (docs/research/launch-languages-2026-09.md — שמונה שפות השקה, עברית נדחית עד שייכנס מודל ייעודי), ולכן הכלל “בדיקה בעברית ובערבית בכל PR” אינו בר‑ביצוע והוחלף בזה: (א) הרצת ה‑locale הפסאודו (packages/i18n/scripts/pseudo.mjs, מחרוזות מוארכות ב‑40%) בכל PR שנוגע במחרוזות או בפריסה, כדי לתפוס חיתוך טקסט; (ב) מעבר RTL ידני דרך המתג settings.advanced.rtl שב‑Settings (I18nManager.forceRTL, גלוי רק ב‑__DEV__) על כל מסך שה‑PR שינה; (ג) ברגע שנשלח locale של עברית או ערבית, הכלל חוזר לנוסחו המקורי ובדיקה בשפה עצמה מחליפה את שלב בʹ. CI מריץ פסאודו‑לוקליזציה (מחרוזות מוארכות ב‑40% עם תווים מיוחדים) כדי לתפוס חיתוך טקסט לפני שיש מתרגם. מחרוזות חדשות נאספות אוטומטית (extraction) ומועברות לצינור התרגום הקיים של אפליקציות התנ"ך (translation-expert + validateLangs), שכבר יודע לתרגם בהקשר ולאמת שלמות; גם מטא‑דאטה בחנויות וצילומי מסך לכל שפה עוברים באותו צינור. מה לא מתורגם: תשובות המודל, שתלויות במודל; לכן בפרטי כל מחסנית (S31, §8) יש שורת "שפות טובות", ובשפה שהמודל חלש בה האפליקציה אומרת זאת במקום להבטיח.

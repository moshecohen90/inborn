## Build

```
cd apps/mobile && npx expo prebuild -p ios --no-install && (cd ios && pod install)
DEVELOPMENT_TEAM=NGCHN95667 ruby scripts/ios-add-storekit-tests.rb ios/Inborn.xcodeproj Inborn
cd ios && xcodebuild -workspace Inborn.xcworkspace -scheme Inborn -configuration Release \
  -destination "generic/platform=iOS" -archivePath build/Inborn.xcarchive -derivedDataPath build/dd \
  -allowProvisioningUpdates DEVELOPMENT_TEAM=NGCHN95667 archive
eval "$(../../../scripts/asc-key-env.sh)"
xcodebuild -exportArchive -archivePath build/Inborn.xcarchive -exportOptionsPlist ExportOptions.plist \
  -exportPath build/export -allowProvisioningUpdates -authenticationKeyPath "$INBORN_ASC_KEY_PATH" \
  -authenticationKeyID "$INBORN_ASC_KEY_ID" -authenticationKeyIssuerID "$INBORN_ASC_ISSUER_ID"
xcrun altool --upload-app -f build/export/Inborn.ipa -t ios --apiKey "$INBORN_ASC_KEY_ID" --apiIssuer "$INBORN_ASC_ISSUER_ID"
```

`--cleanup` is deliberately not in that list (F91: `asc-key-env.sh --cleanup` deletes every stream's staged key, not
the caller's own). The two things a fresh worktree needs were done before anything was built: the **`.models`
symlink existed before `pod install`** (F164 — without it the podspec silently drops Tesseract and Hebrew scans stop
being read), and **`ExportOptions.plist` was recreated by hand**, because it is untracked and the prebuild rewrites
`ios/` without it. `scripts/check-store-env.sh` ran first and reported *store env clean*; `env | grep EXPO_PUBLIC`
was empty for the whole run.

## F265 — the QA variant is its own app

Every device pass until now built the QA/bridge variant under `com.inbornapp.mobile`, the store app's own bundle id,
so it installed **over** the build it was meant to prove; on 23.9 an uninstall of that shared id took Moshe's chats,
documents and vault with it (F144). `APP_VARIANT=development` now builds **`com.inbornapp.mobile.qa`**. Android keeps
one package: Play asset packs and the 6T drivers are keyed to it.

The licence verifier is handed the running build's own bundle id, but only in a build that already allows test
purchases, so a store build still accepts nothing but `APP_BUNDLE_ID`. `apps/mobile/scripts/ios-add-storekit-tests.rb`
reads the id off the app target instead of a literal. Ten tests in `apps/mobile/test/fixes-r55.test.ts`, including the
complement watched failing: the same sandbox proof issued to `com.inbornapp.mobile.qa` comes back `wrong-app` under
the store build's own call, and `wrong-environment` when no test-purchase switch was baked in.

**Proven on the phone, both apps at once** (`scratchpad/ios-build-17/qaseed.status`):

```
QA app: com.inbornapp.mobile.qa 1.0.0 17 Inborn (dev)
store app still installed: com.inbornapp.mobile 1.0.0 17
```

**One thing the QA build path must know.** `APP_VARIANT=development` also changes `name` to `Inborn (dev)`, which
renames the generated Xcode project to `Inborndev.xcodeproj` / `Inborndev.xcworkspace` and clears `ios/` on the
prebuild. Build scripts must **discover** the workspace (`ls -d ios/*.xcworkspace`), never hardcode `Inborn`; the
round-51 recipe in `docs/qa/ios-qa-bridge/README.md` hardcodes it and fails with
`xcodebuild: error: 'ios/Inborn.xcworkspace' does not exist.` The clearing prebuild also deletes
`ios/build/`, so the store archive and IPA must be exported, uploaded and installed **before** the QA variant is
prebuilt from the same worktree.

The QA variant is built with `INBORN_IOS_SHARE_EXT=0`, so no share extension and no App Group are requested for the
new App ID; automatic provisioning registered `com.inbornapp.mobile.qa` on the first attempt.

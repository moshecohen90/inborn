## What is NOT proven yet (needs one human tap)

The four live checks on the phone did not run. The driver that taps the mic and answers the two permission alerts is an XCUITest
(`apps/mobile/ios-tests/VoiceDeviceUITests.swift`, steps via `VOICE_STEPS`), and on iOS 17+ the phone has to approve UI automation
once before any XCUITest runner can attach. Three attempts, the app awake in the foreground, no passcode on the phone:

```
InbornUITests-Runner[1412] Failed to initialize for UI testing: Error Domain=com.apple.dt.XCTest.XCTFuture Code=1000
"Timed out while enabling automation mode."
```

Without automation the microphone and speech-recognition alerts cannot be answered from the Mac, so the real-mic numbers
(system dictation first-partial latency, whisper on the A15 with Metal, TTS on the phone speaker, one hands-free round) are open.
The dev build was uninstalled from the phone afterwards (`devicectl device uninstall app` × 2: app + test runner); the
container with `instant.gguf` / `whisper.bin` / `mmproj.gguf` went with it, so the next stream pushes its own models.

## 30-second script for Moshe (real mic, real speaker)

Install the current dev build (or TestFlight build ≥ 3 once it carries M5b), push `whisper.bin` for the Pro checks, then:

1. Open Inborn → the chat screen. Tap the **microphone** at the right of the composer.
2. Two system alerts, once only: **"Inborn Would Like to Access the Microphone" → Allow**, then **"…Speech Recognition" → OK**.
3. The field border turns amber and the line "Listening… tap the mic to stop" appears. Say: **"What is the capital of France."**
   Expected: the words appear in the field while you speak (system dictation, on-device). Tap the red square to stop; the text stays.
4. Tap **Send**. Expected: an answer with "Paris". Long-press the answer → **Read aloud**. Expected: the phone speaks it within
   about half a second; the row says "Stop reading" while it runs.
5. Pro (whisper): long-press the microphone → **Dictate with Whisper** (if the paywall opens, Pro is not active on this install).
   Say the same sentence, tap the square. Expected: "Transcribing on this phone…" for ~1 s, then the text.
6. Pro (hands-free): long-press the microphone → **Voice conversation**. The dark screen says LISTENING; say a short question and
   stop talking. Expected: TRANSCRIBING → THINKING → SPEAKING (the answer is read out) → LISTENING again. Tap **End**.

If anything differs, a screenshot of the sheet or the error line is enough; every stage also lands in `Documents/dev-run.json`
when the build was made with `EXPO_PUBLIC_AUTOVOICE_SAY` set (see README "Voice + image input").

## Automating it next time (one approval on the phone, then zero hands)

Once Moshe approves UI automation on the phone the first time an XCUITest runs, the whole run is scripted: build with
`EXPO_PUBLIC_AUTOVOICE_SAY="What is the capital of France"` in `ios/.xcode.env.local` (the phone speaks the sentence through its
own speaker one second after each listener opens, volume 0.45), `build-for-testing` for the device, then
`xcodebuild test-without-building` with `VOICE_STEPS` in the `.xctestrun` environment (`launch; tap:mic; allow:10;
waitlabel:composer-input:capital:20; value:composer-input; tap:mic; tap:send; …`). Timings land under `live` in
`Documents/dev-run.json`, screenshots and the driver log are XCTest attachments (`xcresulttool export attachments`).

## The legal gate on the archive itself

The check that had to pass before anything else in this run: read the strings out of the shipped Hermes bundle, not
out of the source tree. Hermes stores any string containing a non-ASCII character as UTF-16LE, so each string is
counted in both encodings. `scratchpad/ios-build-14/bundle-check.py`, run against the archive, with build 13's
identical run kept beside it as the control.

| check | build 13 | build 14 |
|---|---|---|
| `{{DOMAIN}}` / `{{SUPPORT_EMAIL}}` | 6 / 5 (UTF-16LE) | **0 / 0** |
| `{{DEVELOPER_LEGAL_NAME}}` / `{{POSTAL_ADDRESS}}` / `{{EFFECTIVE_DATE}}` / `{{GOVERNING_LAW}}` | 1 / 1 / 1 / 1 | **0 / 0 / 0 / 0** |
| `Status: DRAFT` / `Not yet published` | present | **0 / 0** |
| `Cohen Apps` / `support@inbornapp.com` / `+1-440-847-8502` | absent | **3 / 6 / 2** |
| `Inborn Source-Available Licence 1.0` / `Inborn is not open source` | absent | **1 / 1** |
| `published open-source core` | present | **0** |
| `Secure Enclave` / `hardware-backed` | present | **0 / 0** |
| the real key-store wording (iOS Keychain `WhenUnlockedThisDeviceOnly`, Android Keystore, Windows Credential Manager) | absent | **1 / 2 / 2** |

**The whole bundle was then swept for any remaining `{{…}}` token**, not only the ones on the list. What comes back is
39 distinct UTF-8 tokens and 4 distinct UTF-16LE ones, **41 distinct tokens in all**. One of them is `{{COPYRIGHT}}`,
which `licenceText()` fills when it renders a model licence. **The other 40 are all work-pack prompt templates** —
`{{client_name}}`, `{{patient_ref}}`, `{{tax_year}}`, `{{jurisdiction}}` and so on, filled at runtime from the user's
own input and covered by `packages/core/test/work-packs.test.ts`. No legal or privacy text carries a token:
`grep -o '{{[^}]*}}' docs/legal/` returns
`{{COPYRIGHT}}` twice and nothing else, which is exactly what `apps/mobile/test/legal-texts.test.ts` asserts.

**One check in `bundle-check.py` reports FAIL and it is a false positive.** `Windows Hello` is still in the bundle
once, as the i18n value of `biometric.windowsHello` — the label the lock screen shows a Windows user, which
`packages/core/test/lock-policy.test.ts` explicitly requires ("never uses a brand name on Android, and Windows Hello
on Windows"). F94 was about the **privacy policy** claiming the SQLCipher key is held by Windows Hello; a grep over
`docs/legal/` for `Windows Hello`, `Secure Enclave` and `hardware-backed` returns **zero** hits. The checker's string
is simply broader than the finding.

## Build

```
cd apps/mobile && rm -rf ios && npx expo prebuild -p ios --no-install --clean && (cd ios && pod install)
ruby scripts/ios-add-storekit-tests.rb ios/Inborn.xcodeproj Inborn      # the --clean prebuild drops InbornUITests
cd ios && xcodebuild -workspace Inborn.xcworkspace -scheme Inborn -configuration Release -destination "generic/platform=iOS" \
  -archivePath build/Inborn.xcarchive -derivedDataPath build/dd -allowProvisioningUpdates DEVELOPMENT_TEAM=NGCHN95667 archive
eval "$(../../../scripts/asc-key-env.sh)"
xcodebuild -exportArchive -archivePath build/Inborn.xcarchive -exportOptionsPlist ExportOptions.plist -exportPath build/export \
  -allowProvisioningUpdates -authenticationKeyPath "$INBORN_ASC_KEY_PATH" -authenticationKeyID "$INBORN_ASC_KEY_ID" \
  -authenticationKeyIssuerID "$INBORN_ASC_ISSUER_ID"
xcrun altool --upload-app -f build/export/Inborn.ipa -t ios --apiKey "$INBORN_ASC_KEY_ID" --apiIssuer "$INBORN_ASC_ISSUER_ID"
```

**`--cleanup` is deliberately not in that list.** F91 (build 13) recorded that `scripts/asc-key-env.sh --cleanup`
deletes every stream's staged `AuthKey_*.p8`, not the caller's own; this run never calls it, and removes only the one
file it staged, by name, once no other iOS pipeline is in flight.

**`--validate-app` was skipped this run, deliberately.** On build 13 the validate succeeded and the upload one second
later failed on a key another stream had deleted — F91 fell exactly in the gap between the two calls. Dropping the
validate removes that gap, and `--upload-app` performs the same checks before it transfers: it returned `UPLOAD
SUCCEEDED with no errors` and ASC processed the build to VALID with no rejection. The trade is that a bad binary would
be caught at upload rather than a minute earlier, which costs nothing here.

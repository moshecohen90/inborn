## The first archive was rejected, unuploaded: no Tesseract

**The first archive built clean and was thrown away.** A fresh worktree has no `.models` symlink, and
`modules/doc-extract/ios/DocExtract.podspec` resolves its Tesseract inputs from `INBORN_MODELS_DIR` **or** from
`<repo>/.models`. `pod install` was run without either, so the podspec took its `else` branch: no
`vendored_frameworks`, no `resource_bundles`, and iOS OCR reduced to Vision only. The archive that came out had **no
`DocExtractOcr.bundle` at all** and neither `eng.traineddata` nor `heb.traineddata`, against build 14 which carries
both; the `.app` was **564 MB** against build 14's 572 MB.

**The podspec only warns — it does not fail the build.** `[doc-extract] no Tesseract at …/.models/ocr …; iOS OCR is
Vision only, Hebrew scans will not be read` appears twice in `podinstall.log` and the pod install still exits 0, the
archive still succeeds, and nothing downstream notices. Hebrew scans would simply have stopped being read.

Fixed by creating the `.models` symlink and re-running `pod install` with `INBORN_MODELS_DIR` exported; the vendor
symlinks come back and the second archive carries the bundle. **Nothing was uploaded from the first archive.**

> For any future stream: a fresh worktree needs the `.models` symlink **before `pod install`**, not only
> `INBORN_MODELS_DIR` at prebuild time. The prebuild's own model copy (`withBundledModel`) succeeded from the
> environment variable alone, which is what makes the gap easy to miss — Instant was bundled, only OCR was not.

## Build

```
cd apps/mobile && npx expo prebuild -p ios --no-install && (cd ios && pod install)
ruby scripts/ios-add-storekit-tests.rb ios/Inborn.xcodeproj Inborn
cd ios && xcodebuild -workspace Inborn.xcworkspace -scheme Inborn -configuration Release \
  -destination "generic/platform=iOS" -archivePath build/Inborn.xcarchive -derivedDataPath build/dd \
  -allowProvisioningUpdates DEVELOPMENT_TEAM=NGCHN95667 archive
eval "$(../../../scripts/asc-key-env.sh)"
xcodebuild -exportArchive -archivePath build/Inborn.xcarchive -exportOptionsPlist ExportOptions.plist \
  -exportPath build/export -allowProvisioningUpdates -authenticationKeyPath "$INBORN_ASC_KEY_PATH" \
  -authenticationKeyID "$INBORN_ASC_KEY_ID" -authenticationKeyIssuerID "$INBORN_ASC_ISSUER_ID"
xcrun altool --upload-app -f build/export/Inborn.ipa -t ios --apiKey "$INBORN_ASC_KEY_ID" --apiIssuer "$INBORN_ASC_ISSUER_ID"
```

**`--cleanup` is deliberately not in that list** (F91: `asc-key-env.sh --cleanup` deletes every stream's staged key,
not the caller's own). **`ExportOptions.plist` is not tracked and the prebuild recreates `ios/` without it** — it was
restored by hand before the export, which is a second thing a fresh worktree needs. The export step in this run's
script also takes the `xcodebuild.running` lock, which build 14's script did not: the export runs `xcodebuild` and
could otherwise collide with a gradle release.

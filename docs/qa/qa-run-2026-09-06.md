## Release blockers (fix before any store upload)

1. **16 KB page size: 4 native libraries are 4 KB-aligned** (T33). `libtesseract.so`, `libleptonica.so`, `libjpeg.so`, `libpngx.so` (the OCR dependency of `modules/doc-extract`) have `LOAD` segments aligned to 0x1000. On the API 36.1 16 KB emulator Android shows the system dialog "This app isn't 16 KB compatible. ELF alignment check failed … will be run using page size compatible mode" on every launch until dismissed. Google Play rejects new apps/updates targeting API 35+ that are not 16 KB compliant. Zip alignment of the APK is fine (`zipalign -c -P 16` OK), so this is purely the four ELF files. Evidence: `t33-alignment.txt`, `ps16k-00-compat-dialog.png`.
2. **Manifest declares network-state permissions the privacy documentation says it does not** (T30). Merged release manifest has `ACCESS_NETWORK_STATE` and `ACCESS_WIFI_STATE` (from `expo.modules.network` 57.0.1), `WAKE_LOCK` + `RECEIVE_BOOT_COMPLETED` (androidx.work 2.9.1), `com.google.android.finsky.permission.BIND_GET_INSTALL_REFERRER_SERVICE` (installreferrer 2.2 via Play Billing), plus `USE_FINGERPRINT`, `VIBRATE`. `docs/legal/app-privacy-details.md` §4.2 lists none of these and instead lists `RECORD_AUDIO`/`POST_NOTIFICATIONS`, which are absent. T30's pass criterion says explicitly "no ACCESS_NETWORK_STATE". Fix: add them to `blockedPermissions` in `app.config.ts` (or drop expo-network) and re-sync §4.2. Evidence: `t30-badging.txt`, manifest-merger report.
3. **Android backup includes the database and models** (T39). Merged manifest has `android:allowBackup="true"` and no `dataExtractionRules` / `fullBackupContent`. Spec §10.6 #42 requires models and chats to be excluded. Evidence: merged `AndroidManifest.xml` in `app/build/intermediates/merged_manifests/release`.
4. **`pnpm test` fails on `main`** (fixed on main ≥ b8de94f, kept for the record): `packages/i18n` "every locale has every key of en.json" — 11 keys missing in de, es, fr, ja, pt-BR (`vault.web.managed`, `vault.web.noModel`, `vault.web.status.{ready,partial,missing,chrome}`, `vault.web.size`, `vault.web.storage`, `vault.web.explain`, `vault.web.fullVault`, `settings.advanced.rtl`). Those web-vault strings fall back to English in five languages. Evidence: `gate-test.log`.
5. **AAB asset packs exceed Play's limits (verify at upload).** `inborn_model_sharp` is one on-demand pack of 2,740,945,362 bytes (both shards inside a single pack; Play caps a pack at 1.5 GB) and the four packs total 4.82 GB (Play caps fast-follow + on-demand at 4 GB). The AAB is 4.82 GB. Either split Sharp into two packs and drop/relocate one tier, or expect the upload to be rejected. Evidence: `unzip -l inborn.apks` in this run (`asset-slices/*` sizes).
6. **iOS bundle has no `instant.gguf`** (fixed on main ≥ 70b3de4, TestFlight build 2 ships it) (T02 criterion "bundle contains instant.gguf"). Known open item in the README; the simulator run only worked because the file was copied into the container by hand.
7. **Emergency wipe keeps the passcode hash** (T15, security). After Delete everything → onboarding, Settings shows "Change passcode" instead of "Set a passcode": `wipe.native.ts` deletes only `inborn.db.key`, not `inborn.lock.passcode`. A wiped phone handed on still carries the previous owner's salted hash, and re-enabling the lock silently reuses the old code. Evidence: `ios17-27-relaunch-after-wipe.png` + settings dump after wipe.

## Environment notes for the next run

- Load average on the Mac was 300–430 (many parallel streams). Two arm64 emulators hung in QEMU ("detected a hanging thread 'QEMU2 CPU0'") during sustained inference while an in-guest `tcpdump` was running; the emulator's `-tcpdump` flag is the safe capture.
- Simulator keyboards default to the Mac's Hebrew layout; `idb ui text` types Hebrew letters until `AppleKeyboards` is set to `en_US@sw=QWERTY;hw=Automatic` on the simulator.
- An unsigned simulator build (`CODE_SIGNING_ALLOWED=NO`) has no application-identifier: every Keychain call fails with -34018, so passcode, DB key and licence storage silently break. Build simulators with the default ad-hoc signing.
- The 16 KB image: `system-images;android-36.1;google_apis_ps16k;arm64-v8a` (installed this run with the command-line tools 13114758; the old `tools/bin/sdkmanager` no longer runs on JDK 21).
- `bundletool install-apks` pushes all four packs (4.8 GB) to `/sdcard`; hand-pushing only the fast-follow slice never completed delivery.

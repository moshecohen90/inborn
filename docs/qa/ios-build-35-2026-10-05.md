## The `.qa` twin first, and why there were two

**Twin 1** was built with build 34's recipe from the same commit: `APP_VARIANT=development EXPO_PUBLIC_QA=1
EXPO_PUBLIC_AUTOPROMPT=file INBORN_IOS_SHARE_EXT=0`, also exported for `xcodebuild` (17:32:40 → 17:36:13). Its checks:
`INBORN_QA_BRIDGE_V1` 1×, stamp a04f3640dc89, the same round 130 markers, and Instant plus its pack byte-identical
to the archive's (`raw/qa-verify.txt`). It was installed fresh at 17:37:23 and ran J1, J3, J5 and J2.

Twin 1 refused the bridge's `network` step: *"this build cannot simulate a lost connection"*. The offline switch
(`vault/devOffline.ts`) asks `devBuild()` (`licence/buildKind.ts`), which is `devBundle || (devVariant && devModelHost)`.
So a Release twin needs `EXPO_PUBLIC_DEV_MODEL_HOST` as well, and build 34's recipe did not set it. **Twin 2** is the
same commit and the same environment plus `EXPO_PUBLIC_DEV_MODEL_HOST=localhost`, with no `EXPO_PUBLIC_MODELS_BASE_URL`.
That only adds localhost to the allowed hosts, so every download still came from `models.inbornapp.com`. It was built
18:00:00 → 18:03:25 (stamp a04f3640dc89 1×, models identical to the archive's) and installed over twin 1 at 18:05:32.
It ran J5's wipe and the J4 doors. **For the next build: add `EXPO_PUBLIC_DEV_MODEL_HOST=localhost` to the twin's
environment** if the pass uses the `network` step.

The twin was uninstalled at 18:12:17, before the store app was touched.
